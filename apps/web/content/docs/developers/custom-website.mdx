# Custom Website API

This guide is for developers connecting a website, app or other sales channel to BookOne. It is written for any custom site (Next.js, Laravel, Django, a headless storefront). For WordPress, the packaged plugin is described in [WooCommerce](/docs/developers/woocommerce).

**How it works.** BookOne is the single source of truth. Each website is a **connection** (a sales channel) in BookOne. Your server:

1. imports the products BookOne **publishes** to your channel ([Catalog API](/docs/developers/catalog));
2. keeps stock and product changes current with the **change feed**;
3. sends **orders** back; BookOne holds their stock, invoices them, records payment and tracks delivery;
4. shows customers the order status, courier and tracking number that staff enter in BookOne.

- Base URL: `https://<your-bookone-host>/api/commerce/v1`
- Spec: [OpenAPI 3.1 JSON](/api/commerce/v1/openapi.json) (public, no key needed)
- Version: **v1**. Changes are additive; see the [changelog](#changelog).

## 1. Set up a sandbox connection

Done by a BookOne Owner or Admin in **Company → Commerce Integrations**:

1. **New connection**: name the store, choose **Custom website**, environment **Sandbox**, and pick the shop or warehouse whose stock the website sells.
2. **Developer** tab → **Issue scoped key**. Copy the key from the one-time dialog; BookOne shows only its prefix afterwards.
3. **Developer** tab → **Add sample catalog** (sandbox only) gives you about 48 sample products to build against: 3 brands, a category tree, paint ranges with 6 colour variants, photos, weights and stock. It posts no accounting.
4. **Products** tab: publish the products your website may sell.
5. **Payments** tab: choose the account each payment method settles into.
6. **Settings** tab: posting mode, safety buffer, which payment methods hold stock while unpaid, couriers.

Check the key:

```bash
export BOOKONE_BASE='https://your-bookone-host/api/commerce/v1'
export BOOKONE_KEY='bkc_sand_prefix_secret'   # keep on your server only

curl -sS -H "Authorization: Bearer $BOOKONE_KEY" "$BOOKONE_BASE/connection"
```

`GET /connection` returns the channel (`channel.id`, `channel.name`), stock location, currency, `taxMode`, `timezone`, `safetyBuffer`, `allowBackorder`, the key's `scopes` and a `capabilities` object. **Check `capabilities` before using a feature**; a missing or `false` flag means it is not available yet.

## 2. Conventions

| Topic | Rule |
|---|---|
| Auth | `Authorization: Bearer bkc_…`. The key is a server secret: never put it in browser code, theme files or logs. Rotate keeps the old key valid for 24 hours; revoke ends it at once. |
| Scopes | `catalog` (products, changes), `inventory` (stock), `order` (submit and read orders), `lifecycle` (order events). |
| Money | Decimal string with 2 decimals: `"1250.00"`. |
| Quantities | Decimal strings: `"2"`, `"0.5"`. |
| Time | ISO 8601 with offset. |
| IDs | Opaque strings. Do not parse them. |
| Paging | `cursor` and `limit` (default 50, max 250). Responses are `{ items, nextCursor }`; `nextCursor` is `null` at the end. |
| SKU batches | Endpoints that take `sku` accept up to 100: repeat `sku=` or pass a comma list. |
| Revisions | Products, variants, prices and stock carry a `revision` that only increases. Ignore an update whose revision is lower than the one you hold. |
| Caching | GET responses carry a weak `ETag`. Send it back as `If-None-Match`; an unchanged response is `304 Not Modified`. |
| Rate limit | 600 requests per minute per key. Every response has `X-RateLimit-Limit` and `X-RateLimit-Remaining`; `429` carries `Retry-After`. |
| Request id | Responses include `requestId` (body and `X-Request-Id`). Quote it when asking for support. |
| Idempotency | `POST /orders` requires `Idempotency-Key`. A replay returns the original receipt with `replayed: true`. Reuse a key only for the same body. |
| Errors | `{ ok: false, code, error, requestId, details? }`. See [API errors](/docs/developers/errors). |

## 3. Recommended sync loop

```text
First run:
  GET /connection                       -> check capabilities, remember timezone/currency
  GET /catalog/categories, /catalog/brands, /catalog/attributes
  GET /catalog/products?include=variants,images,prices,inventory,attributes&limit=250
      follow nextCursor until null; upsert each product by id; download images
  GET /changes                          -> keep nextCursor as your change checkpoint

Every 30-60 seconds:
  GET /changes?cursor=<checkpoint>
      for each item (dedupe on item.id):
        product / mapping / publish -> GET /catalog/products/{productId}?include=... and upsert
        inventory                   -> update stock for item.sku from the payload
        order                       -> update the customer's order view, send emails
      save nextCursor only after applying the page
  On 422 CURSOR_EXPIRED: re-import /catalog/products and /inventory, then /changes without a cursor.

Nightly safety net:
  GET /catalog/products?updatedSince=<last full sync>
  GET /inventory
```

### Prices

Each product and variant carries a `price` object (with `include=prices`):

```json
{
  "currency": "LKR",
  "priceListId": "3f6c…",
  "price": "1119.00",
  "compareAtPrice": "1250.00",
  "sale": { "price": "999.00", "startsAt": "2026-12-01T00:00:00+05:30", "endsAt": "2026-12-07T23:59:59+05:30", "active": true },
  "tiers": [{ "minQty": "6", "price": "1050.00" }],
  "effectivePrice": "999.00",
  "revision": 1764150720000,
  "updatedAt": "…"
}
```

- Charge `effectivePrice` for one item. It is the sale price while `sale.active` is true, otherwise `price`.
- For larger quantities, use the highest tier whose `minQty` is at or below the quantity, when it is lower than `effectivePrice`.
- Show `compareAtPrice` struck through ("was"). It is only sent when it is higher than `price`.
- `priceListId` is the list this channel sells at (`default` = the BookOne sell price). Products not on the list use their BookOne sell price.
- Customer groups: add `customerGroup=wholesale` to any catalog or pricing call to get that group's list when one exists. Otherwise you get the channel list.
- A `price` change arrives on the feed when a price is edited, the channel's list is switched, or a sale starts or ends.

Re-check prices at checkout with `GET /pricing?sku=A,B,C` (1 to 100 product or variant SKUs):

```bash
curl -sS -H "Authorization: Bearer $BOOKONE_KEY" "$BOOKONE_BASE/pricing?sku=WN-COT-8ML-CHWHITE,WN-COT-8ML-LEMON"
```

```json
{ "items": [{ "sku": "WN-COT-8ML-CHWHITE", "productId": "…", "parentProductId": "…", "price": { "effectivePrice": "999.00", "…": "…" } }], "missing": [], "priceListId": "3f6c…", "customerGroup": null }
```

## 4. Stock

```bash
curl -sS -H "Authorization: Bearer $BOOKONE_KEY" "$BOOKONE_BASE/inventory?sku=WC0001,WC0002"
```

Each item: `sku`, `productId`, `onHand`, `committed`, `available`, `quantity`, `safetyBuffer`, `allowBackorder`, `revision`, `asOf`.

- `available = onHand − committed − safetyBuffer`, never below 0. **Sell against `available`** (`quantity` is the same number, kept for older clients).
- `committed` is stock held for open web orders that are not invoiced yet (cash on delivery, bank transfer; see section 6).
- The owner sets the channel **safety buffer** (for example keep 1 unit for the shop) and whether the site may **take backorders** when available is 0. A product can also allow backorders on its own; see `allowBackorder` on the catalog product.
- `/inventory` covers the products published to your channel (`scope: "published"`). POS sales, invoices, purchases, stock adjustments and web orders all change it, and each change appears on the feed within seconds.

## 5. Change feed

```bash
curl -sS -H "Authorization: Bearer $BOOKONE_KEY" "$BOOKONE_BASE/changes?cursor=$CHECKPOINT"
```

Items arrive in `revision` order: `{ id, revision, kind, productId, sku, payload, createdAt }`. Delivery is at least once, so de-duplicate on `id`.

| kind | When | Payload |
|---|---|---|
| `product` | A product, variant or its photos changed in BookOne, or it was published or unpublished | `action` (`updated`, `published`, `unpublished`), `productId`, `variantId`, `sku`. Re-read the product |
| `price` | The channel price of a product or variant changed (price edited, list switched, sale started or ended) | `productId`, `variantId`, `sku`, `price` (the full price object) |
| `inventory` | Stock or held stock changed | `sku`, `onHand`, `committed`, `available`, `quantity`, `locationId` |
| `order` | BookOne changed one of your web orders | `externalId`, `action`, `status`, `paymentStatus`, `fulfilment`, `documentNumber` |
| `mapping` | A BookOne product was linked to one of your listings | `action: "applied"`, `sku`, `bookoneProductId`, `externalProductId`, `externalVariantId` |
| `publish` | (legacy publish queue) a product was queued for you, or you acknowledged it | `action` (`queued`, `claimed`), `claimId`, `sku` |
| `catalog` | (legacy) a linked product changed | `sku`, `name`, `unit` |

`order` actions: `stock_held`, `needs_review`, `confirmed`, `paid`, `posted`, `dispatched`, `delivered`, `cancelled`, `refunded`, and `event:<kind>` for your own events. Use them to email customers ("Your order has been dispatched, tracking …").

## 6. Orders

### Submit

```bash
curl -sS -X POST "$BOOKONE_BASE/orders" \
  -H "Authorization: Bearer $BOOKONE_KEY" \
  -H "Idempotency-Key: order-create-WLK-100245" \
  -H "Content-Type: application/json" \
  -d '{
    "externalId": "WLK-100245",
    "currency": "LKR",
    "placedAt": "2026-11-26T10:00:00+05:30",
    "customer": { "name": "Nimal Perera", "email": "nimal@example.com", "phone": "+94771234567" },
    "lines": [
      { "externalLineId": "1", "sku": "WN-COT-8ML-CHWHITE", "quantity": "2", "unitPrice": "1119.00", "discountAmount": "0.00", "taxAmount": "0.00" }
    ],
    "shippingAmount": "450.00",
    "discountAmount": "0.00",
    "total": "2688.00",
    "payment": { "status": "pending", "method": "cod", "amount": "2688.00" }
  }'
```

- `externalId` is your order number. It is immutable and unique per channel.
- `total` must equal lines + shipping − discounts + tax, or the order is held for review.
- The response is **202 Accepted** with a receipt. 202 means BookOne has the order; read `status` to see what happened. Use `POST /orders/validate` with the same body for a side-effect-free check.
- Lost response? Send the same body with the same `Idempotency-Key`.

### What happens next (`status`)

| status | Meaning |
|---|---|
| `received` | Taken in. Waiting for payment, or the connection is in Preview |
| `needs_review` | Staff must check it (`reviewReason` says why: stock, totals, tax, unmapped SKU). Nothing was posted |
| `posted` | A sales invoice exists (`documentNumber`); stock is deducted |
| `paid`, `fulfilled`, `cancelled`, `refunded`, `partially_refunded` | Later states |

`GET /orders/{externalId}` returns the same receipt plus `paymentStatus`, `stock` and `fulfilment`.

### Payment methods and settlement

Send `payment.method` as the name your site uses: `cod`, `bank_transfer`, or your gateway's id. Any name is accepted. The owner maps each name to a BookOne account under **Payments**. A paid order then posts as a settled sale into that account (`settlement: "settled"`); with no account set, the invoice stays open (`settlement: "not_configured"`). `GET /payment-methods` lists the methods your channel has used, where each settles, and whether it holds stock.

### Cash on delivery and bank transfer hold stock

An order with `payment.status: "pending"` and a method in the channel's hold list (by default `cod` and `bank_transfer`) **holds its stock on receipt**: `stock: "committed"`, and `available` drops at once on the website and at the POS. If stock is short, the order is `needs_review` and nothing is held.

- Cancelled (your event or staff in BookOne): the hold is released (`stock: "released"`).
- Paid (your `paid` event, or staff **Mark paid** when the courier remits the cash) with posting on: the invoice posts and the hold becomes the stock deduction (`stock: "consumed"`).
- Card and gateway orders arrive `paid` and post at once; they do not need a hold.

### Tax

For a VAT-registered company, send the tax you charged in `taxAmount` (per line or for the order). If it matches the company's VAT rate on the net after discounts, the order posts as a tax invoice. An order with no tax, or a different amount, is held for review rather than posted without VAT. A company that is not VAT registered posts untaxed orders as commercial invoices.

### Fulfilment from BookOne

Staff work web orders on the **Orders** tab: Confirm, Mark paid, Dispatch (courier and tracking number), Mark delivered, Cancel, Refund, Refund and restock.

```json
"fulfilment": {
  "status": "shipped",
  "confirmedAt": "2026-11-27T09:10:00Z",
  "shipments": [
    { "id": "…", "carrier": "City Courier", "trackingNumber": "TRK123456", "trackingUrl": "https://track.example/TRK123456",
      "shippedAt": "2026-11-27T15:10:00Z", "deliveredAt": null }
  ],
  "stock": "consumed"
}
```

`status` is one of `unfulfilled`, `confirmed`, `shipped`, `delivered`, `returned`, `cancelled` (`picking`, `packed`, `out_for_delivery` are reserved). Every change is an `order` item on the change feed.

### Events from your website

`POST /orders/{externalId}/events` with `externalEventId` (idempotent) and `kind`:

| kind | Use |
|---|---|
| `paid` | Payment confirmed after the order was sent (for example a gateway callback) |
| `cancelled` | The customer or your shop cancelled. Releases held stock; a posted order gets a linked return with restock |
| `fulfilled` | Your site shipped it (if you fulfil outside BookOne) |
| `refunded` | `amount`, `externalRefundId`, `restock`, and for restock `lines: [{ externalLineId, quantity }]` |

If BookOne cannot book a cancel or refund, the order moves to **needs review** with the reason and staff use **Retry**; your call still gets a receipt.

## 7. Older integration paths (still supported)

- `GET /products` lists only products **linked** to your listings (mapping). New integrations should import from [`/catalog/products`](/docs/developers/catalog) instead.
- **Publish queue**: staff queue products under **Products → Publish from BookOne**. Your server reads `GET /catalog/candidates`, creates listings with your own ids, then `POST /catalog/acknowledge` with `bookoneProductId` and `externalProductId`. The same ids replay; a different id for an acknowledged product is `409 CONFLICT`.
- Linked products count as published, so `/inventory` and the catalog keep working for older sites.

## 8. Node example

```js
const BASE = process.env.BOOKONE_BASE; // https://host/api/commerce/v1
const KEY = process.env.BOOKONE_KEY;   // server only

async function bookone(path, init = {}) {
  const res = await fetch(`${BASE}${path}`, {
    ...init,
    headers: { Authorization: `Bearer ${KEY}`, 'Content-Type': 'application/json', ...init.headers },
  });
  if (res.status === 429) {
    await new Promise((r) => setTimeout(r, Number(res.headers.get('Retry-After') ?? 5) * 1000));
    return bookone(path, init);
  }
  const body = res.status === 304 ? null : await res.json();
  if (!res.ok && res.status !== 304) throw new Error(`${body.code}: ${body.error} (request ${body.requestId})`);
  return body;
}

// Full catalog import
let cursor = null;
do {
  const page = await bookone(`/catalog/products?include=variants,images,prices,inventory,attributes&limit=250${cursor ? `&cursor=${cursor}` : ''}`);
  for (const product of page.items) await upsertProduct(product); // your code
  cursor = page.nextCursor;
} while (cursor);
```
