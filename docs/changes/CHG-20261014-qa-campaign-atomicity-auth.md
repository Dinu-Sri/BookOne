- Intended before/after behaviour with a concrete example:
  - Before: two concurrent 350 payments against a 600 invoice both allocated (cash 700, GL AR −100). Replay of `receiveCustomerPayments` `{ok, paidCount}` without `id` was treated as still running. Viewer collected/refunded hire money and transferred stock. Failed deposit/transfer left txn+empty journal or header/layers without rollback. Files restore ignored mismatched `dataSha256`. Empty journal entries looked balanced (0=0); posted AR without a transaction was restorable when GL also happened to match.
  - After: `allocateDocumentPayment` locks the document `FOR UPDATE` inside one transaction and re-reads `balanceDue`. Idempotency completion recognizes `{ok}` / `{paidCount}` and writes the finished payload on success and failure. Collect/refund/hire charges require `rental.dispatch.write` + rental module + liquid tender (1000/11xx/12xx); post+event update is one transaction. Stock transfer requires `inventory.transfers.write` + inventory module + owned locations; all qty/layer/movement writes are one transaction with stable locks. Costing helpers rethrow database errors. Files pack compares `dataSha256` when both sides have it. Restore refuses empty journal entries and posted AR/AP without a live `transactionId`.
